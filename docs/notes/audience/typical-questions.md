# 受众典型问题（T5）

> 用途：选题会快速定位“这期要回答谁的什么问题”。每个问题附 1 个示例回答角度（不是完整答案）。

## A 层（核心客户方）

| 典型问题 | 示例回答角度 |
|---|---|
| 1. 我们的 AI 项目总停在 demo，怎么在 90 天内进入稳定流程？ | 先挑 1 条高频流程做试点，按“输入口径、责任人、验收标准、回退方案”四步固化。 |
| 2. 我怎么向管理层证明这件事值得持续投入？ | 用“周期缩短、错误率下降、返工减少”三类指标做前后对比，先证小闭环再扩面。 |
| 3. 没有完整数据中台，是不是没法做 AI-native？ | 先做低侵入层（检索、摘要、质检）并保留人工复核，再逐步接入核心系统。 |
| 4. 组织里谁来担责，谁来执行，谁来兜底？ | 以 IC/DRI/PC 划分：IC 保能力质量，DRI 保结果，PC 保协作机制。 |
| 5. 如何避免“为了上 AI 而上 AI”？ | 每个试点必须绑定业务目标和停机条件，达不到阈值就回退，不做无边界实验。 |

## B 层（合作方 / 生态共建）

| 典型问题 | 示例回答角度 |
|---|---|
| 1. 联合合作里我们怎么分工，才能不互相补位？ | 先出 RACI 和里程碑验收表，写清输入输出与责任升级路径。 |
| 2. 技术栈不一致时，合作项目怎么落地？ | 先做最小接口协议和数据口径对齐，再谈深度集成。 |
| 3. 合作收益如何量化，避免只出力不出结果？ | 统一线索归因和转化口径，按阶段复盘投入产出比。 |
| 4. 一次项目经验如何沉淀为可复制方案？ | 项目结束前强制产出三件资产：模板、脚本、案例复盘。 |
| 5. 多方协作如何避免第二个月失速？ | 固定节奏（周会+月复盘）与问题升级机制前置，不靠临时沟通。 |

## C 层（潜在员工 / 贡献者）

| 典型问题 | 示例回答角度 |
|---|---|
| 1. 我会用 AI 工具，但怎么变成可交付成果？ | 从“工具使用”切到“结果责任”，每周至少沉淀 1 个可复用资产。 |
| 2. 这里强调速度，会不会牺牲成长？ | 速度和成长通过复盘机制绑定：交付后 24 小时内复盘并更新方法库。 |
| 3. 没有很强技术背景，能在 AI-native 团队发挥价值吗？ | 可以，从问题定义、流程设计、质检运营切入，先做可衡量贡献。 |
| 4. 如何判断自己是不是适合这种协作模式？ | 看是否能在不完整信息下推进并对结果负责，而不只完成指令。 |
| 5. 贡献者合作会不会沟通成本太高？ | 通过明确协作协议、验收标准、反馈周期降低摩擦。 |

## D 层（行业观察者）

| 典型问题 | 示例回答角度 |
|---|---|
| 1. 你们观点和市场上已有叙事相比，新增价值是什么？ | 给出“判断+证据+边界”，避免复述行业共识。 |
| 2. 这些判断有没有可验证的数据或案例？ | 每篇至少给 1 个数据点和 1 个可追溯来源。 |
| 3. 你们如何看待当前 AI 组织化落地的主要瓶颈？ | 从组织、流程、能力三个层面拆解，不只谈模型能力。 |
| 4. 这套方法适用范围和不适用范围是什么？ | 主动写清边界条件，降低误读和过度外推。 |
| 5. 为什么你们的内容值得被引用？ | 输出结构化图表和可复用框架，降低二次传播成本。 |
