# Persona B：合作方 / 生态共建（T2）

> 目标：让内容不仅“讲我们自己”，还能回答“潜在合作方如何与我们一起做成事”。

## B 层定义

B 层受众是“能与我们形成联合交付、渠道协同、技术互补或品牌共建的人/组织”。

## 共性画像（B 层）

- 典型职位（映射，不作为分层依据）：生态合作负责人、渠道总监、解决方案负责人、技术合作负责人、社区运营负责人
- 典型组织规模：20-5000 人（从垂直咨询团队到平台型企业）
- 职责镜头（按需求分组）：
  1. 评估合作投入与回报的人（多见于 DRI / 商务负责人）
  2. 评估技术互通与交付边界的人（多见于 IC / 解决方案负责人）
  3. 评估联合团队协作效率的人（多见于 PC / 生态运营负责人）
- 日常阅读的 3 个平台（细化到账号/栏目/内容）：
  1. 微信公众号：
     - 常看：产业互联网、SaaS 商业化、企业服务案例号
     - 常读内容：联合方案、客户案例、渠道政策与分工机制
  2. 小红书：
     - 常看：咨询/培训类机构号、B2B 增长实践号
     - 常读内容：方法论切片、合作打法复盘、落地工具模板
  3. 抖音：
     - 常看：企业服务销售类账号、商业访谈类账号
     - 常读内容：合作案例拆解、销售打法、组织协同经验
- 最关注的 5 个话题：
  1. 联合方案如何定义职责边界与收益分配（DRI/PC）
  2. 交付过程中工具链、数据与接口如何互通（IC）
  3. 如何把一次合作沉淀为可复制的标准产品包（DRI）
  4. 联合品牌曝光如何转化为线索与成交（DRI/PC）
  5. 多方协作下的风险与争议如何前置管理（PC）
- 典型痛点 3 条：
  1. IC 维度：双方技术栈异构，接口约定和验收标准不统一，联调成本高
  2. DRI 维度：合作目标表述一致但 KPI 不一致，项目推进容易中途失焦
  3. PC 维度：联合团队节奏不一致，沟通机制缺失导致协作摩擦反复出现
- 典型反对意见 2 条：
  1. “合作很好听，但最后都是我们的人在补位，边际收益不清楚。”（DRI）
  2. “没有标准化交付资产，合作不可复制。”（IC/PC）
- 判断内容“值不值得看完”的 3 个信号：
  1. 是否明确合作分工、输入输出和验收口径（DRI/IC）
  2. 是否给出真实联合案例的成功与失败边界（DRI）
  3. 是否包含可复用模板（SOW、RACI、里程碑）而非泛泛理念（PC）

## 画像样本 01

### B1｜区域交付型咨询公司合伙人

- 典型职位：咨询公司合伙人 / 解决方案总监
- 典型组织规模：80 人（以行业咨询 + 项目交付为主）
- 日常阅读的 3 个平台：微信公众号（行业案例）、小红书（交付方法切片）、抖音（商业化经验）
- 最关注的 5 个话题：
  1. 如何把你们的方法快速打包进现有咨询产品线（DRI）
  2. 项目里技术与咨询责任边界怎么划（IC/DRI）
  3. 交付周期压缩后质量如何保证（IC）
  4. 联合售前材料是否可直接复用（PC）
  5. 合作签约后的利润分配与续费机制（DRI）
- 典型痛点 3 条：
  1. 售前承诺与交付能力不匹配，导致返工（DRI）
  2. 顾问与工程团队语言体系不统一（PC）
  3. 项目资产沉淀差，复用率低（IC）
- 典型反对意见 2 条：
  1. “如果只增加概念包装，不增加交付效率，合作意义不大。”（DRI）
  2. “客户复杂场景下，标准方案容易失效。”（IC）
- 判断内容“值不值得看完”的 3 个信号：
  1. 是否提供行业场景化模板（DRI）
  2. 是否说明复杂场景下的适配边界（IC）
  3. 是否有“第一次合作 30 天计划”（PC）

## 画像样本 02

### B2｜SaaS 平台生态负责人（全国渠道体系）

- 典型职位：生态合作负责人 / 渠道总监
- 典型组织规模：1200 人（平台产品 + 渠道销售 + 生态伙伴）
- 日常阅读的 3 个平台：微信公众号（平台生态策略）、抖音（销售与管理内容）、小红书（伙伴运营经验）
- 最关注的 5 个话题：
  1. 联合产品如何减少渠道培训成本（PC）
  2. 伙伴交付质量如何标准化（IC/PC）
  3. 如何设计可持续的激励与分层机制（DRI）
  4. 共创内容如何带来有效线索（DRI）
  5. 区域伙伴能力差异如何分级管理（PC）
- 典型痛点 3 条：
  1. 区域渠道能力参差，标准复制慢（PC）
  2. 平台能力更新快，伙伴跟进滞后（IC）
  3. 线索归因与收益分配争议多（DRI）
- 典型反对意见 2 条：
  1. “合作后如果不能提升渠道成交率，就不值得。”（DRI）
  2. “没有统一培训包和验收机制，规模化会失控。”（PC）
- 判断内容“值不值得看完”的 3 个信号：
  1. 是否有可执行的伙伴分层策略（DRI/PC）
  2. 是否有标准化 enablement 物料清单（PC）
  3. 是否量化合作后的线索到成交提升（DRI）
