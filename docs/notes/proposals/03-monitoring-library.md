# 提案 03：监控库 v0（种子资源 / 评分规则 / 周执行）

> 状态：Draft，供 PR 内讨论。合并前不会改动 `docs/notes/2026-04-23-init-plan.md`。

## 1. 背景

监控库是整条内容运营链路的"进货端"。它决定了选题池的质量上限——监控库稳定，栏目才能稳定产出；监控库跟热点，栏目也只能跟热点。

improve_suggestion 第 10–11 章给了英文种子库和一套评分规则。本 PR 的目标是：

- 把英文种子库原样接纳，确认分层模型
- 明确**中文种子库第一版由 intern 调研补齐**（这是 intern 独立拿下的一块实操任务）
- 敲定素材评分、字段结构和周执行节奏

本 PR 不建实际的飞书/Notion 表，只定义"表结构和工作流应该长什么样"。实际表由 intern 在 PR 合并后搭建。

## 2. 提议

### 2.1 监控库的 3 类输入（不做"抓更多信息"，做"稳定产出 3 类输入"）

1. **理念输入**：AI-native 组织、未来组织形态、协作方式变化。
2. **方法输入**：agent、workflow、memory、tool use、context engineering 等实践。
3. **行业输入**：竞品、产品发布、用户讨论、案例与 signal。

### 2.2 监控库 5 层分层

| 层级 | 作用 | 典型来源 |
|---|---|---|
| L1 官方发布层 | 一手信息 | 官方 Newsroom、官方工程博客、开发者文档 |
| L2 深度作者层 | 高质量判断 | 独立作者博客、newsletter、播客 |
| L3 社区讨论层 | 用户真实问题与表达 | X、Reddit、Hacker News、即刻、知乎 |
| L4 竞品观察层 | 谁在抢叙事空间 | 竞品官网、更新日志、创始人发言 |
| L5 内部沉淀层 | 外部输入转可复用资产 | 选题池、素材池、术语表、案例表 |

### 2.3 监控库总表字段（v0）

| 渠道 | 官网 / RSS / X / 小红书 / 微信 / Reddit / Medium |

### 2.6 素材评分规则（4 维度，各 1–5 分）

| 维度 | 评分说明 |
|---|---|
| 相关性 | 与公司理念（AI-native 组织）直接相关程度 |
| 时效性 | 现在发是否还有价值（signal 类更敏感） |
| 可转内容性 | 能否转成长文 / 短内容 / 视频 |
| 原创增量空间 | 能否加入自己的框架与判断 |

**门槛**：总分 ≥ 16 才进入本周选题会候选。低于 16 的素材进入素材池归档，不强制转化。

### 2.7 表载体选型（飞书多维表 vs Notion）

| 对比项 | 飞书多维表 | Notion |
|---|---|---|
| 国内访问稳定性 | 高 | 中 |
| 多维视图（看板/日历/表格） | 支持 | 支持 |
| 自动化 / webhook | 支持（飞书机器人） | 支持（较贵） |
| 与 content-collector-skill（PR #4）集成 | **作者已官方支持飞书文档** | 需自己接 API |
| 团队协作习惯 | 依赖公司是否主用飞书 | 依赖个人 |

**推荐飞书多维表**。最强的理由是 PR #4 里 `content-collector-skill` 原生落盘到飞书文档，能省掉中间层。如果公司不用飞书，再退回 Notion。

### 2.8 周执行节奏

| 时间 | 动作 | 负责人 | 输出 |
|---|---|---|---|
| 每天上午 | 扫描 A 级来源 | intern | 新增素材入池 |
| 每天下午 | 去重、摘要、打标签 | intern | 素材池更新 |
| 周一上午 | 汇总 ≥ 16 分素材 | intern | 候选选题清单 |
| 周一下午 | 选题会 | mentor + intern | 本周 3 个选题 |
| 周三 | 补充竞品与社区反馈 | intern | 选题修正 |
| 周五 | 记录本周最高产出来源 | intern | 来源优先级调整 |

## 3. 讨论点

- [ ] **Q1 中文种子表承包** 中文种子库由 intern 在 v1 合并后 2 周内完成第一版，是否可接？
- [ ] **Q2 表载体** 飞书多维表 vs Notion：公司主用哪个？是否有第三选项（Airtable / 金山轻维表）？
