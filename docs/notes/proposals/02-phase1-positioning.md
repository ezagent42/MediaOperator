# 提案 02：第一阶段定位（目标 / 受众 / 栏目 / 周节奏 / RACI）

> 状态：Draft，供 PR 内讨论。合并前不会改动 `docs/notes/2026-04-23-init-plan.md`。

## 1. 背景

这是 v1 里"决策密度最高"的一章，对应 improve_suggestion 的第 2、4、5、6 章。内容决定了：

- 第一阶段为谁服务（主 / 次目标）
- 每周必须产出什么（产能兜底）
- 谁拍板、谁执行、谁审校（协作规则）

本 PR 不写正式稿，**只搭决策草案 + 留讨论位**。最终措辞由 mentor + intern 在评论区敲定。

## 2. 已定的上游决策（来自 mentor）

这些是 mentor 已经拍过板的前提，**不重新讨论**：

- **主阵地组合**：微信公众号 + 小红书，抖音作为辅助分发阵地
- **第一阶段主目标**：吸引认同 AI-native 组织理念的客户与合作方
- **次目标**：吸引认同该工作方式的未来员工与生态参与者
- **第一批固定栏目（3 个）**：
  1. AI-native 组织周观察
  2. 一个 DRI 会怎么拆这个问题
  3. 这周值得看的 5 个 signal

本 PR 是在这些前提之上，把颗粒度细化到可执行。

## 3. 提议

### 3.1 第一阶段交付目标（8 周内）

按 improve_suggestion 第 2.1(3) 节，落地为 5 条可衡量结果：

- [ ] 公众号 + 小红书两个主阵地账号完成申请、认证、基础装修。
- [ ] 连续 8 周完成固定频率发布，无中断。
- [ ] 建成选题池、素材池、术语表、排期表各 1 份（可落地于飞书多维表）。
- [ ] 3 个固定栏目各完成至少 6 期。
- [ ] 沉淀第一批高质量互动对象（合作方、从业者、候选人）不少于 30 人，进入 CRM 雏形。

**阶段边界**：

> 第一阶段不追求全平台铺开，不追求爆量，重点是建立清晰表达、稳定节奏和高质量受众匹配。

### 3.2 目标受众与核心信息框架

**受众分层**：

| 层级 | 定义 | 在第一阶段的权重 |
|---|---|---|
| A. 核心客户方 | 已经在思考"AI 进组织"这件事的甲方决策者 / 研发负责人 | 高 |
| B. 合作方 / 共建生态 | AI infra、咨询、媒体、产品生态同路人 | 高 |
| C. 潜在员工 / 贡献者 | 认同理念的工程师、产品、研究、内容人 | 中 |
| D. 行业观察者 | 记者、分析师、投资人 | 低（间接触达） |

**核心信息翻译表**（内部术语 → 对外表达）：

| 模块 | 内部表达 | 对外建议表达 |
|---|---|---|
| 组织理念 | AI 网络为中心，人作为末端 | 未来组织不再围绕固定层级运转，而是围绕 AI 驱动的信息网络和协作拓扑运转 |
| IC | 个体贡献者 | 提供某类独特能力的人或 AI 节点 |
| DRI | 直接责任人 | 负责定义目标、重构流程、优化人机协同结构的人 |
| Player-Coach | 玩家-教练 | 一边亲自参与工作，一边帮助人和 AI 更快融入协作网络的人 |

**内容总纲（建议写入 v1 第 2 章结尾）**：

> 智道元生希望讨论的，不只是"AI 工具怎么用"，而是"当 AI 成为组织中心节点后，人的角色、流程和协作方式会如何改变"。

### 3.3 三个固定栏目的定位草案

| 栏目 | 核心目的 | 主阵地 | 辅助分发 | 建议频率 | 长度 | 内容原型 |
|---|---|---|---|---|---|---|
| AI-native 组织周观察 | 把一周里最值得聊的组织/工作方式变化讲清楚 | 公众号 | 小红书图文 + 抖音口播 | 每周 1 期（固定周三） | 公众号 1500–2500 字；小红书图文 3–5 张；抖音 60–90 秒 | 选 1 个 signal → 放回组织语境 → 给出我们的判断 |
| 一个 DRI 会怎么拆这个问题 | 把理念翻译成可操作的方法论 | 公众号 | 小红书图文 | 每 2 周 1 期（奇数周五） | 公众号 2000–3500 字；小红书 5–7 张 | 选 1 个真实问题 → 写一个 DRI 的拆法 → 留下可复用清单 |
| 这周值得看的 5 个 signal | 轻更新，承接监控库输入，建立"必看"心智 | 小红书 | 公众号周末合辑 + 抖音快评 | 每周 1 期（固定周日） | 小红书 1 图 + 500 字；公众号合辑 800–1200 字 | 5 条素材 + 每条 50 字点评 + 1 条"这周我们在看什么" |

**栏目之间的关系**：

- 「5 个 signal」是**上游**，给另外两个栏目喂素材。
- 「周观察」是**主品**，承担品牌心智。
- 「DRI 会怎么拆」是**深度品**，承担方法论沉淀。

### 3.4 周产能表（最小可执行版本）

对应 improve_suggestion 第 6.5 节。

| 类型 | 每周产出 | 栏目归属 | 说明 |
|---|---|---|---|
| 公众号深度长文 | 1 篇 | 周观察（每周）/ DRI 拆题（隔周） | 主品 |
| 小红书图文 | 2–3 篇 | 5 个 signal + 周观察切片 | 覆盖辅助分发 |
| 抖音短视频 | 2 条 | 周观察口播 + signal 快评 | 延展触达 |
| 周度 signal 汇总 | 1 条 | 5 个 signal | 周日发 |
| 复盘记录 | 1 次 | 内部 | 每周五 |

**内容拆分规则**：

- 1 篇长文 = 2 篇小红书切片 + 1 条抖音口播脚本 + 1 条预告 thread（为未来上 X 做储备）
- 1 次周度 signal 汇总 = 候选选题 3 条（喂给下周选题会）
- 1 个案例拆解 = 1 篇长文 或 2 条短内容

### 3.5 每周流程草案

| 时间 | 动作 | 输出 | 主责 |
|---|---|---|---|
| 周一 上午 | 监控库扫描 + 素材入池 | 本周素材池快照 | intern（运营 IC） |
| 周一 下午 | 选题会（30 分钟） | 本周 3 个选题 | mentor（DRI）定优先级 |
| 周二 | 长文大纲 + 短内容角度 | 大纲 v1 | intern 起稿 |
| 周三 上午 | 长文发布（周观察） | 公众号发布 | intern 执行 |
| 周三 下午 | 切片到小红书 + 抖音 | 两个辅助阵地发布 | intern |
| 周五 | 5 signal 收尾 + 复盘 | signal 汇总草稿 + 复盘表 | intern |
| 周日 | 5 signal 发布（小红书为主） | 小红书 + 公众号合辑 | intern |

### 3.6 RACI 分工草案

沿用 improve_suggestion 第 7.1 节，**代入 mentor/intern 具体身份**：

| 环节 | DRI（mentor） | Player-Coach（待定） | IC（intern） |
|---|---|---|---|
| 阶段目标 | A | C | I |
| 监控库维护 | C | C | R |
| 选题优先级 | A | C | R |
| 大纲审校 | A | R | C |
| 内容生成 | C | C | R |
| 理念一致性把关 | C | A | I |
| 发布与排期 | A | C | R |
| 数据复盘 | A | C | R |

（R = Responsible 执行；A = Accountable 拍板；C = Consulted 提供意见；I = Informed 被同步）

**SLA 草案**：

- 选题确定后 24h 内出大纲
- 大纲确认后 48h 内出首稿
- 发布后 24h 完成首轮数据记录
- 每周五固定复盘，每月末做主题回顾

## 4. 讨论点
