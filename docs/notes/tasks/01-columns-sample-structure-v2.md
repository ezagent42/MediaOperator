# 任务 01：T1-T3 样稿结构（修订版 v3）

- [x] **T1** 写《AI-native 组织周观察》第 01 期样稿
  - 选当周（或上周）一个真实 signal 作为切入
  - 结构：
    - A. 开场定位（120–180 字）：一句话说清本期关注的变化 + 适用读者 + 本文给出的判断范围
    - B. signal 事实层（180–260 字）：只写可验证事实，至少包含 1 个时间点、1 个主体、1 个动作
    - C. 变化解读层（400–600 字）：回答“为什么是现在发生”“为什么不是孤立事件”
    - D. 组织影响层（600–900 字）：从组织结构、流程、岗位、治理 4 个维度里至少选 2 个展开
    - E. 行动建议层（250–400 字）：给出 3 条可执行动作，格式统一为“动作 + 适用条件 + 预期收益”
    - F. 一句话带走（40–80 字）：可直接放封面的结论句
  - 必须包含：
    - 至少 2 条来源（正文内标注）
    - 至少 1 个“反直觉”判断句（不是新闻复述）
    - 至少 1 个“如果不做会怎样”的风险提示
  - 同步放一版小红书切片在同文件末尾（3–5 张图配文）

- [x] **T2** 写《一个 DRI 会怎么拆这个问题》第 01 期样稿
  - 选一个真实问题（建议从我们自己近期工作里挑）
  - 结构：
    - A. 问题原貌（200–350 字）：背景、约束、目标冲突，明确“为什么这题值得拆”
    - B. DRI 目标定义（120–200 字）：写清成功标准、失败边界、时间窗口
    - C. 拆解步骤（3–5 步，每步 180–300 字）：
      - 每步固定 4 小块：输入 / 动作 / 产出 / 风险
      - 每步必须给出“是否可并行”判断
    - D. 复用清单（每步 3–5 条）：沉淀成 checklist，不写成散文
    - E. agent 接管地图（250–450 字）：按“可全自动 / 半自动 / 必须人工”三层划分
    - F. 复盘与下一步（150–250 字）：这套拆法下次怎么复用、哪些前提会失效
  - 必须包含：
    - 至少 1 个真实失败点或返工点（避免理想化叙述）
    - 至少 1 张文本表（步骤 x 责任人 x 交付物）
    - 至少 1 条“人机协作分界线”原则

- [x] **T3** 写《这周值得看的 10 个 signal》第 01 期样稿
  - 结构：
    - A. 单页 HTML 图文模式：后续不再维护“小红书 1 图版 + 公众号合辑版”双版本
    - B. 页面结构：
      - Hero：本期主判断 + 期数/栏目标签
      - 10 条 signal 卡片：每条包含来源图标、编号、标题、事实、判断、展开说明、执行建议
      - 本周总结：1 个共同趋势判断 + 3–4 条后续观察方向
      - 来源区：统一放页尾，保留原始链接
    - C. 内容要求：
      - 每条 signal 都必须可独立阅读
      - 每条 signal 都必须有“事实 / 判断 / 执行建议”三层
      - 页面中只保留一组 1–10 signal，避免上方摘要和下方正文重复
    - D. 来源备忘：统一放页尾，按“事件 + 媒体/机构 + 日期 + 链接”格式列出
  - 必须包含：
    - 每条 signal 都要有固定判断句（例如“`我们的判断`”）
    - 每条 signal 都要有可执行建议，不可只做摘要搬运
    - HTML 页面必须包含图片元素（来源 logo / favicon / 相关视觉资产均可）
